FAQ

Evaluating Rook

Is Rook production-ready? Who runs it?

Yes. The Rook Ceph operator was declared stable in 2018, and Rook is a CNCF graduated project. Organizations run it in production at petabyte scale.

Who runs Rook Rook docs
What happens to my data if the Rook operator goes down?

Your data keeps flowing. Rook is not in the Ceph data path: applications read and write directly to Ceph. Management tasks such as upgrades and configuration changes resume when the operator is back.

Storage architecture
Rook or cephadm?

Both are installers recommended by the Ceph documentation. Choose Rook if you run Kubernetes and want storage managed through its APIs. Choose cephadm for Ceph clusters outside Kubernetes.

Ceph docs: Installing Ceph
Is Rook a fork of Ceph? Does it slow Ceph down?

No. Rook runs the official upstream Ceph images, and the usual ceph tools and the Ceph Dashboard work as before. For the best performance, give Ceph its own networks.

Network providers Ceph Dashboard
What do I need?

A Kubernetes cluster on amd64 or arm64 nodes, with local disks or block volumes for Ceph. One VM is enough to try Rook; production starts at three nodes.

Prerequisites
How do upgrades work, and how often is Rook released?

Change the Ceph version in your spec and Rook rolls the upgrade out across the daemons, checking Ceph’s health as it goes. A new minor release ships about every four months, and the two most recent are maintained.

Upgrade guide Supported versions
Is it secure?

Rook can encrypt data at rest and in transit, integrates with external key managers such as HashiCorp Vault, and has a private vulnerability disclosure process through the CNCF. It was audited by Trail of Bits in 2019.

Security policy Encryption docs
Can I get commercial support?

Yes. The companies on our support page offer Rook support and services, and several commercial storage products are built on Rook.

Support providers

Running Rook

What if the Kubernetes control plane goes down?

Running Ceph daemons and mounted volumes keep serving data. New pods, volumes and mounts wait until the control plane is back, so plan its availability like any other dependency of your storage.

Storage architecture
What if I lose the whole Kubernetes cluster?

Your data is on the Ceph disks, not in Kubernetes. The disaster recovery guide shows how to bring an existing Rook Ceph cluster up in a new Kubernetes cluster.

Disaster recovery guide
Can I use an existing Ceph cluster?

Yes. In external mode, Rook connects your Kubernetes workloads to a Ceph cluster you already run, for example one managed by cephadm.

External cluster
Can I run it in the cloud or air-gapped?

Yes. In the cloud, Rook builds Ceph on block volumes from your provider’s storage class. For air-gapped sites, mirror the images to your own registry.

PVC-based clusters Private registries
Who maintains Rook? Is it controlled by one vendor?

Maintainers come from several companies and research organizations, and more than 580 organizations have contributed. Governance rules bar any single company from holding a majority on the steering committee.

Maintainers Governance
Can I use Rook only for S3, or only for block volumes?

Yes. Each storage type is a separate resource, so you deploy only what you need: an object store, block pools, a filesystem, or any mix.

Object storage Block storage
What is the license?

Rook is Apache 2.0. Ceph is LGPL (2.1 or 3.0).

Rook license Ceph license
