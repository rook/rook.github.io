Deploy Rook

Open-source, cloud-native storage for Kubernetes

Rook declaratively deploys and operates distributed block, file and S3 object storage on your Kubernetes clusters.

See who runs Rook in production

You describe the cluster. Rook builds and runs it.

Describe the cluster you want: which disks to use, how to protect your data (copies or erasure coding) and where to place it, and which pools and S3 object stores to create. Apply it, and Rook provisions the rest.

  • Upgrade Ceph by changing one line. Rook rolls it out daemon by daemon and checks cluster health as it goes.
  • Drain a node for an OS or Kubernetes upgrade. Rook takes its disks offline only when that is safe for your data.
  • New disks go to work as they appear. To replace a failed disk, mark it and swap it.
  • App teams request S3 buckets and credentials in YAML.

Why Rook

Cost efficiency

  • 2× less raw space than three copies, same redundancy, with erasure coding
  • NVMe for metadata, HDDs for data: flash-speed metadata at HDD cost
Erasure coding

Runs everywhere Kubernetes runs

On bare metal or in any cloud, on local disks or your provider's block volumes.

Cluster types

Open source, no vendor lock-in

Rook (Apache 2.0) and Ceph (LGPL) run on hardware you choose, and no single company controls the project.

Governance

Hardware fails, your data stays

Ceph keeps each copy on a different host, rack or zone, rebuilds lost copies on its own, and spreads data onto new disks as you add them.

FAQ

All questions
What happens to my data if the Rook operator goes down?

Your data keeps flowing. Rook is not in the Ceph data path: applications read and write directly to Ceph. Management tasks such as upgrades and configuration changes resume when the operator is back.

Storage architecture
Rook or cephadm?

Both are installers recommended by the Ceph documentation. Choose Rook if you run Kubernetes and want storage managed through its APIs. Choose cephadm for Ceph clusters outside Kubernetes.

Ceph docs: Installing Ceph
Is Rook a fork of Ceph? Does it slow Ceph down?

No. Rook runs the official upstream Ceph images, and the usual ceph tools and the Ceph Dashboard work as before. For the best performance, give Ceph its own networks.

Network providers Ceph Dashboard
What do I need?

A Kubernetes cluster on amd64 or arm64 nodes, with local disks or block volumes for Ceph. One VM is enough to try Rook; production starts at three nodes.

How often is Rook released?

A new minor release ships about every four months, and the two most recent are maintained.
